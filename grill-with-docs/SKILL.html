grill-with-docs

跟它一輪輪對談，把你要的東西想清楚，順手讓它把結論寫成文件。

Run a /grilling session, using the /domain-modeling skill.

使用 /domain-modeling 技能，執行一場 /grilling session。

📖 教學解說

grill-with-docs 是主流程的第一站。它的核心是 /grilling 原語——一個回合制的訪談，agent 問問題、你做決策。關鍵區別是它有狀態：會把學到的東西寫進 CONTEXT.md 和 ADR（Architecture Decision Records），讓後續 session 可以從上次停下的地方繼續。

與 /grill-me 的差別：grill-me 是無狀態的，不寫任何東西到磁碟。如果你在工作目錄（有 repo 的地方），永遠選 grill-with-docs，因為它留下的紙本痕跡是後續 to-spec、to-tickets、implement 的素材。

💡 Worked Example

情境：你要為一個 Node.js 專案設計「用戶匯出 CSV」功能。

  1. 呼叫 /grill-with-docs，描述你的點子
  2. Agent 會問：「匯出的資料範圍是什麼？全部用戶還是有篩選條件？」→ 你決定「支援日期範圍篩選」
  3. Agent 會問：「匯出格式除了 CSV 還需要 JSON 嗎？」→ 你決定「先只做 CSV」
  4. 這些決策會被寫進 CONTEXT.md，標記為 ADR
  5. 如果 grill 發現需要實際跑一下才能確認某些問題（例如 CSV 串流的效能），建議你繞道 /prototype

⚠️ 常見錯誤

  • 在 grill 之前就 compact context——grill-with-docs 的價值在於它能在同一個 context window 中保持連續性。Compact 會切斷這個連續性。
  • 回答得太模糊——Agent 問「你要什麼？」，你回答「你覺得呢？」。Grill 的設計是你做決策，agent 負責問到你沒得閃。模糊的回答只會讓 grill 拖更久。
  • 跳過 grill 直接 implement—— grill 的目的是把需求想清楚。跳過它 = 在不清楚要做什麼的情況下寫程式碼。
  • 把 grill-me 當成 grill-with-docs 的替代——如果你在工作目錄中，永遠選 grill-with-docs。grill-me 沒有留下任何文件。

✅ 練習 / 驗收清單

  • □ 能說明 grill-with-docs 和 grill-me 的差別（有狀態 vs 無狀態）
  • □ 知道 grill 的核心機制（agent 問、你答、決策寫進 CONTEXT.md）
  • □ 每個問題都有給出具體答案，而不是模糊回應
  • □ 如果 grill 發現需要實際跑，會建議繞道 prototype
  • □ Grill 完後有 CONTEXT.md 和 ADR 作為後續素材

🚀 進階真實情境 Worked Example

情境：你把舊版「會員制」改造成「訂閱制 + 用量計費」的混合模型。這牽涉計費、授權、資料遷移，你在 repo 中開始 grill-with-docs。

  1. 第一輪：Agent 問「舊會員的權益在訂閱制下如何保留？」→ 你：「舊權益對齊為 Legacy 方案，不再銷售但保留」。
  2. Agent 追問邊界：「用量計費的『用量』以什麼為單位？」→ 你：「以 API call 次數」。Agent 把它寫進 CONTEXT.md 並標記 ADR（計費單位定義，難以逆轉）。
  3. Agent 質疑詞彙：「你剛才說『過期』和『停用』，是同一個狀態嗎？」→ 你意識到兩者不同——過期是時間到、停用是管理員凍結。新增兩筆詞彙表定義。
  4. Grill 進入需要實際跑的決策：「用量計費的即時扣減還是月底結算？」→ 這需要跑 prototype 驗證效能，agent 建議繞道 /prototype，用 /handoff 來回搭橋。
  5. 回來後，agent 把 prototype 驗證的結論（月底結算、非同步計數）寫進 CONTEXT.md，並在 to-spec 時當作既有決策引用。

設計決策：混合計費最關鍵的決策是區分「過期」與「停用」這兩個看似同義的詞。若沒被 agent 挑戰，schema 可能只用一個 status 欄位吞掉兩種語義，未來客服與工程溝通時就開始翻譯。grill-with-docs 的價值正是在決策定案的那一刻就地寫入，讓詞彙衝突在寫程式之前就被解決。

🔬 深入原理擴充

grill-with-docs 是主流程「有狀態」的關鍵，因為它把 /grilling（訪談原語）與 /domain-modeling（詞彙紀律）縫在一起。兩者的分工是：grilling 決定「要回答哪些問題」，domain-modeling 決定「用什麼詞回答並把它記下來」。少了 domain-modeling，grill 的結論只活在對話裡；少了 grilling，domain-modeling 沒有問題可挑戰。它們的組合就是「想清楚」＋「留證據」。

對 AI coding assistant 而言，CONTEXT.md 扮演跨 session 的長期記憶——它讓一個全新 agent 進到 repo 就能用對的詞彙工作，而不必重新猜「cancel 到底是什麼」。這正是 handoff、to-spec、implement、code-review 一連串技能能無縫接力同一份工作的原因。

陷阱案例：很多人以為 grill 得「越久越好」，於是在同一個 session 裡無止境地追問，直到 context 逼近 smart zone。真相是：grill 的目的不是窮盡所有問題，而是讓「該決策的」都決策完。超過某個點後，新問題開始重複舊問題的變體，邊際收益遞減。技能明說「逼近 smart zone 時在最近的階段邊界 compact」——不要硬撐到品質劣化才收手，那只是把「想清楚」變成「想太多」。

🏆 進階挑戰題

  1. 詞彙挑戰：使用者在 grill 中說「訂單被退貨後就 refund」。CONTEXT.md 定義 refund 為「使用者要求退款」、無 return 定義。寫出你作為 agent 會挑戰的一句話，以及你會提議的詞彙表更新。
  2. 階段邊界決策：grill 進行到一半，context 用了 80%，還有三個主題沒談。列出 Continue / clear / handoff / subagent / compact 五個選項，並說明此刻你該選哪個、為什麼。
  3. 決定繞道：grill 卡在「即時扣款 vs 月底結算」的效能問題上。說明你建議繞道 prototype 的完整流程（handoff 出去→prototype→handoff 回來→更新 CONTEXT.md）。
