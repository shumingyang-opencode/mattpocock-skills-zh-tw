RESOURCES.md Format

RESOURCES.md 格式

RESOURCES.md is the curated set of trusted sources for this topic. Knowledge for explainers should be drawn from here, not from parametric guesses. Wisdom comes from the communities listed here.

RESOURCES.md 是此主題受信任來源的精心策畫清單。講解的知識應該從這裡取得，而不是來自參數式猜測。智慧來自這裡列出的社群。

Structure

結構

# {Topic} Resources

## Knowledge

- [Book: _The Science and Practice of Strength Training_ — Zatsiorsky & Kraemer](https://example.com)
  Foundational text on programming and adaptation. Use for: anything to do with periodisation, recovery, intensity zones.
- [Article: "How Much Should I Train?" — Greg Nuckols (Stronger By Science)](https://example.com)
  Evidence-based review of volume landmarks. Use for: weekly set targets per muscle group.

## Wisdom (Communities)

- [r/weightroom](https://reddit.com/r/weightroom)
  High-signal subreddit, moderated against bro-science. Use for: programme critique, plateau troubleshooting.
- Local: Tuesday strength class at {gym name}
  Use for: real-time coaching feedback on lifts.

Rules

規則

  • High-trust only. Prefer primary sources, recognised experts, peer-reviewed work, and communities with strong moderation. If a resource is marketing dressed as education, leave it out.
  • Annotate every entry. A bare link is useless in three months. Add one line: what it covers and when to reach for it.
  • Group by Knowledge / Wisdom. Mirrors the philosophy in SKILL.md. It is fine for a resource to appear in only one group.
  • Surface gaps explicitly. If no good resource exists for an area the mission needs, write a ## Gaps section listing what is missing. This drives future search.
  • Prune ruthlessly. A resource that turned out to be wrong, shallow, or off-mission should be removed, not buried. Better five sharp sources than thirty mediocre ones.
  • Record community preferences. If the user has opted out of joining communities, note it here so future sessions don't keep proposing them.
  • 只要高信任度。 優先選擇主要來源、公認的專家、同儕審查的成果，以及有嚴格審核的社群。如果一個資源是披著教育外衣的行銷，就不要它。
  • 為每個條目加上註解。 一個裸露的連結三個月後就沒用了。加上一行：它涵蓋什麼，以及何時取用它。
  • 按 Knowledge / Wisdom 分組。 呼應 SKILL.md 中的哲學。一個資源只出現在其中一組是可以的。
  • 明確呈現缺口。 如果任務需要但某個領域沒有好的資源，寫一個 ## Gaps 段落列出缺少什麼。這驅動未來的搜尋。
  • 無情地修剪。 一個被證明錯誤、淺薄或偏離任務的資源應該被移除，而不是被埋藏。五個銳利的來源勝過三十個平庸的。
  • 記錄社群偏好。 如果使用者選擇不加入社群，在這裡註明，這樣未來的 session 不會一直提議它們。
