跟全景圖／學習路線不同的另一把鑰匙：技能可以跨區，別被一格綁死

這是 aihero.dev/skills 官方對這套技能的分類法——六個區，從「設定一次」到「墊底的可重用層」。技能可能同時出現在多個區（例如 triage 同時在塑形與維護、writing-for-agents 同時在生產力與參考層）。

📖 教學解說

六大區是 aihero.dev 官方分類法——跟學習路線（L0–L4）是不同的切入角度。學習路線是「按順序走」，六大區是「按功能分類」。同一個技能可能出現在多個區——例如 triage 同時出現在「塑形」和「維護」。

六個區的邏輯：入門（佈場地）→ 主流程（點子→交付）→ 塑形（決定做什麼）→ 維護（修 bug、重構）→ 生產力（非程式碼工作流）→ 參考層（詞彙和設計語言）。選哪個區取決於你現在在做什麼，不是你想學什麼。

✅ 練習 / 驗收清單

  • □ 能說出六大區各自的名稱和用途
  • □ 知道同一個技能可以出現在多個區
  • □ 知道六大區 vs 學習路線的差別（分類 vs 順序）
  • □ 能根據「我現在在做什麼」選對的區

🚀 進階真實情境 Worked Example

情境：你的一天從三件事開始——線上回報「付款失敗」、產品經理丟來一個「會員忠誠度計畫」的點子、你自己想趁空檔整理一直出問題的訂單模組。你用六大區快速定位每件事。

  1. 付款失敗：是「有東西壞了」→ 維護區，走 /diagnosing-bugs（先建一條會變紅的迴圈再談假設）。
  2. 忠誠度計畫：是「點子→交付」→ 主流程，走 /grill-with-docs 起手；若大到裝不下單一 session，會切到 塑形區 的 /wayfinder。
  3. 整理訂單模組：是「讓程式碼庫對 agent 更好作業」→ 維護區，走 /improve-codebase-architecture 掃描深化機會。
  4. 三件事各有歸位，不需要互相等：維護區的 bug 與重構可以並行，主流程的點子走自己的節奏。你也能在任一點隨時翻 參考層（/codebase-design 的詞彙）來把維護區的討論講精準。

設計決策：六大區的核心洞察是同一套技能可以服務多種情境——triage 同時在塑形（決定做什麼）與維護（消化湧入的請求）；writing-for-agents 同時在生產力與參考層。分區是「看你現在在做什麼」的分類工具，不是技能的分類歸檔——這跟學習路線「按順序走」的視角互補。

🔬 深入原理擴充

六大區本質上是對「技能使用情境」的使用者視角分類法。學習路線（L0–L4）是「流程視角」——它假設你正沿著主流程前進；六大區是「情境視角」——它假設你手上有一堆不同性質的任務，需要快速把每個任務歸位。兩者不是競爭關係：主流程中的某一步，在六大區裡也正好落在對應的區（implement 在主流程也在執行區），差別只在切入問題的方式。

「技能可以跨區」不是分類的缺陷，而是技能設計的「多面性」特徵——一個好的技能往往能服務不只一種情境。以 research 為例：在主流程中它是支援（查資料餵給 grill），在塑形區它是探索工具（查決策等待的事實）。這提醒使用者：別被分類綁死——分類是幫助你找技能的地圖，不是技能的邊界。

陷阱案例：很多人把六大區當成「技能的永久歸屬」，於是認定「research 是支援層技能，所以主流程不該用它」——結果在 grill 卡在「第三方 API 到底支援什麼」時，寧可自己慢慢讀文檔，也不肯翻 /research。真相是：分類是「什麼情境該想到什麼技能」的索引，不是「什麼技能屬於哪裡」的標籤。需要查資料就翻 research、需要詞彙就翻 codebase-design，不管它出現在哪一區。被分類綁死，等於把地圖誤當成領土。

🩺 診斷式疑難排解表

症狀可能原因解決方案
想找技能時在錯誤的區翻找把分類當成技能的永久歸屬，而非情境索引用「我現在在做什麼」反推區；跨區技能（如 triage、research）允許出現在多區
把學習路線與六大區混用、順序錯亂兩種視角（流程 vs 情境）被當成同一套主流程推進用學習路線；手上雜務定位用六大區；兩者互補不互斥
遇到線上 bug 卻先去主流程安排沒把「有東西壞了」歸到維護區事故走維護區的 diagnosing-bugs（先建迴圈），不排進點子→交付的主流程
大型綠地工程誤走主流程的 grill-with-docs沒認出「大到裝不下單一 session」該切塑形區判斷「單一 session 裝得下嗎」；裝不下就切 wayfinder（塑形區）
詞彙／參考技能沒被「隨時可翻」地使用把參考層當成「最後才學」的內容需要時就翻：詞彙衝突用 domain-modeling、查事實用 research，不必等某個階段

🏆 進階挑戰題

  1. 情境歸位：五個情境（新功能點子、P1 事故、外部 PR 湧入、想整理架構、學習新語言）各自落在六大區的哪一區，可能跨哪幾區？
  2. 雙視角對照：以 triage 為例，說明它在學習路線與六大區各自的位置與角色，並解釋「同一個技能兩種分類」為何不是矛盾。
  3. 分類批判：有人主張「把六大區併入學習路線，只留一套」。從「流程視角 vs 情境視角」的差異論證為什麼兩套並存比併成一套好。
